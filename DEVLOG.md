30. ERROR/self-inflicted: dry-run returned `StackUnderflow` for even trivial contract `contract A{uint public x=1;}`. Cause: GenericTransaction.input is a struct {input:Option<Bytes>, data:Option<Bytes>}; I passed a bare hex string and polkadot-js mis-decoded it (silently for some payloads, throwing for others). Fix: `input: { input: data }`. Not a chain bug, but the runtime API type is undocumented (I found it by reading api.call metadata).

Post-run cross-check (scripts/verify-final.mjs -> evidence/post-run-verification.txt): contract's blockhash(377183) == reviveApi.ethBlockHash(377183) (0x88bb…2fa0) and != the Substrate block hash of that block (0x965f…f218). I.e. in pallet-revive `blockhash()` returns the *Ethereum-format* block hash, which is a hash built by the block author over the block's tx set — not the Substrate header hash. Found empirically; undocumented. Consequence for fairness: block author can influence it by tx selection/ordering (grinding), so this is weaker than a real VRF/beacon.
