## Decisions, deviations, and limitations
- Quip QVRF is described as operational for its own Quantum Echoes project, but its developer docs explicitly say the request interface, fees and certification parameters are not final, no function names/parameters or installable packages/code examples. Marketing page has Request Access; no public documented QVRF API to integrate. Do not invent a Quip endpoint or repurpose the unrelated optimization `SolverQuip` or wallet SDK.
- Chose Australian National University quantum-number API as closest *actually documented* quantum source, not drand (classical distributed beacon). New AQN API needs user-supplied signup/API key; no credentials invented. Legacy ANU API is deprecated and rate-limited; offer explicit legacy test mode only. Public quantum bytes are operator-trusted and do NOT have Quip transcript/commitment proof. No claim of independently certified quantum randomness.
- Design bounds entrants/winners to 1024 and draws via rejection sampling over uint16 to avoid modulo bias. One 1024-sample request per draw; record all raw values and selection trace. Service is single-process, single-operator prototype with local files, not a regulated tamper-proof lottery. No network fallback to pseudorandomness.
