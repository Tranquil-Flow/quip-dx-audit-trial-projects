# Porting Base Sepolia TipJar to Quip Aglais testnet

## Result and scope

The unchanged TipJar was deployed to Aglais EVM (chain 20033). A native AGLS tip from a testnet-only, Quip-SHRINCS-signature-controlled smart account succeeded: transaction `0x22e949e7ac3f758ae0402e9d518aff33a5fcf9ebca8e8a97f99d4b6956bc5ccb`, receipt status 1; `Tipped.tipper = 0xcCAdF8e5736efE303B832c0cEdfFD452BA714e6C`, not the gas relayer. A second tip through the localhost web API also succeeded: `0xaf0e5ac9865cc44e04cf6e264b1dac996990836694a2238bf1f251c60a22633e`. The PQ signer was generated with Quip's current beta SDK and the signature accepted by a deployed Quip SHRINCS256sKeccak verifier. **This wrapper is not the official Quip Account product.** There is no official factory/verifier deployment on Aglais, no wallet extension connection to the custom account, and no production-grade key rotation/recovery. See `RESULT.md` for addresses and `DEVLOG.md` for all trials and errors.

## Smallest workable changes

- Kept `src/TipJar.sol`, `script/Deploy.s.sol` and the five existing contract tests unchanged: native value, `msg.sender`, ERC-20 `approve`/`transferFrom`, events, and withdrawals are still ordinary EVM operations. Added three wrapper tests instead of modifying TipJar authorization.
- Switched `web/app.js` from Base Sepolia chain 84532 to Aglais chain 20033, RPC `https://evm-rpc.aglais.quip.network`, native display `AGLS`, and `web/deployment.json` for the public deployed TipJar address. An injected EVM wallet now offers `wallet_addEthereumChain` if switching to an unknown network fails (4902). The historical event reader can use the public RPC independently of an injected wallet. The original ethers v6 tip and optional ERC-20 approve/pull path remains. Corrected token event display to read actual ERC-20 decimals rather than assume 18.
- Added `src/QuipTipAccount.sol`: a minimal account whose `execute` requires the ERC-7913 magic result from Quip's on-chain SHRINCS verifier. The authorization hash binds domain, chain ID, account address, account nonce, target, value and data. Nonce increments before making the external call (rollback on revert). A separate classical EOA *pays gas only*; `TipJar.tip` sees the PQ account as `msg.sender`. The account does not expose an EOA-owner bypass.
- Added project-local disposable credential generation, guarded deployment and tip scripts under `scripts/`; secrets and signing-state live only in ignored `./keys`. Check the **Substrate genesis** and EVM chain ID before signing; never equate EVM block-zero hash with Substrate genesis. Advance/durably persist the one-time leaf counter *before* constructing signatures, including unsuccessful attempts. Browser PQ mode uses `node scripts/serve.mjs`, bound to 127.0.0.1 with same-origin JSON POST, validated/limited amounts and serialized signing. This is for a locally controlled test key, not a hosted custodial service. `scripts/setup-verifier.sh` reproduces the pinned upstream AGPL verifier build inside the project.

## What looked portable but was not

1. **Quip's asset layer is not automatically live on Quip's compute-chain testnet.** [Quip Accounts](https://developers.quip.network/docs/quip-interlock-protocol/quip-accounts.md) describes a smart-contract account on an *existing host chain*, not an Aglais EVM built-in account. The documented `@quip.network/ethereum-sdk@beta` (`0.3.0-beta.8`) throws `UnsupportedNetworkError` for Aglais chain 20033. Its predicted factory `0xA2B2F71456a799FCf4EF7A3111c4B96b3e928cc8`, verifier `0xF2f9E6D692da41b089c3c261c41509669eEc5567`, and CreateX singleton `0xba5Ed099633D3B313e4D5F7bdc1305d3c28ba5Ed` all have empty code on Aglais. The official factory deployment scripts require CreateX, an owner/operator and a vetted implementation; they cannot just be pointed at this RPC. An EOA or ordinary injected wallet on Aglais alone is **not** a Quip post-quantum account.
2. **Matching SDK/verifier versions mattered.** Docs say to install `@quip.network/ethereum-sdk@beta` and `@quip.network/hashsigs-wasm@rc`, not npm `latest` (stale). The first verifier source branch (`shrincs-v101`, commit 69e2996) was incompatible: the WASM signer verified locally but on-chain returned `0xffffffff`, so its account was never funded. The later `shrincs-main` source pinned to commit `90df8e9ba79ee6964ebd03b6ac04d1435978ec3d` accepted a signature only when called with the SDK's `statefulRawMessageHash(commitment, operationHash)`. Its public verifier checks the supplied 32 bytes, rather than adding that SDK hash binding at the verifier boundary; the wrapper therefore explicitly computes and verifies the bound hash. This was established by actual calls returning `0xffffffff` for the unbound hash and selector `0x024ad318` for the bound one, before signing a real tip. This pairing is an experimental integration, not a vendor-supported deployment. Three earlier testnet artifacts (one older verifier, two superseded wrapper accounts) remain on-chain, unfunded; see DEVLOG.
3. **Base-style gas limits did not port.** `eth_estimateGas` for TipJar deployment was ~778 million EVM gas on pallet-revive, vs a planned 3-million fixed limit; the script now estimates and adds a 20% buffer. EVM RPC shows 18-decimal AGLS while faucet reports 12-decimal native units. Faucet root is a 404 and browser preflight is unsupported; use `POST /request` from shell with `{"dest":"0x..."}`. The faucet returned a Substrate extrinsic hash rather than EVM transaction hash. The authoritative [developer portal llms.txt](https://developers.quip.network/llms.txt) gives Aglais Substrate genesis `0x59e064bddd49a920d1392693c728c3bf9867f2cf3e0f8fea8c2498b389b0c286`; the EVM block-zero hash is *different* (`0x41330c6653307a2666648c9a8e217acd54e9b47ac1d5c49902efc2d017b51814`). Checking only EVM chain ID is insufficient: 20033 was also used by a retired network.
4. **Toolchain and docs drift.** The former `docs.quip.network/docs/...` and `quip.gitbook.io/docs/...` links tested here returned 404; `docs.quip.network` redirects to `developers.quip.network/docs`, where `.md` mirrors and `/llms.txt` are usable. Local Foundry rejected two newer ignored-warning names in vendor's `foundry.toml`, so the setup script removes those two names in the *project-local clone* only; no verifier source change. Initial npm install failed executing esbuild (`spawnSync ... -88`), then a network timeout; offline cached install with `--ignore-scripts` succeeded. Quip SDK exposes no working Aglais factory address nor a ready-made browser PQ signer flow, so a localhost-only signing bridge was necessary for a functional UI without pasting a private key into a web page.

## Security and expectations

A tip from the wrapper has actual Quip SHRINCS on-chain authorization, but this is **not** interchangeable with the vendor's full Quip Account, extension, ERC-4337 bundler/paymaster, opt-in upgrade mechanism, recovery, or robust multi-device leaf state. The example cannot rotate its key and should not hold value. Its signed `execute` permits arbitrary targets (including ERC-20 approvals), so keep its seed private; the provided localhost API deliberately only constructs bounded native-value calls to TipJar. The server serializes its own requests but not independent CLI invocations. Do not reuse stateful leaves, restore a stale leaf file, expose the server, or put any of these keys on a mainnet. `README.md` gives step-by-step local/testnet use.

Vendor improvements that would remove most work: publish an Aglais-supported account deployment or explicit statement that the asset layer is unavailable there; list live per-chain factory/verifier/CreateX addresses with code checks; pin a matching `ethereum-sdk`/WASM/verifier revision and show end-to-end `execute(TipJar.tip)` examples; document Aglais EVM gas mapping, faucet response/decimals, and both Substrate-genesis and EVM-block-zero identification.
