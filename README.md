# Quip Solana devnet PQ wallet CLI

Uses Quip Network's `@quip.network/solana-sdk@0.0.1`, the deployed Quip program, and its supported WOTS+ one-time post-quantum signatures. The distinct H1-H4 hybrid suites advertised in Quip's other npm package are NOT supported by this Solana SDK. WOTS+ is the only usable supported choice here. This is a devnet-only demo, not an audited production wallet.

## Run

Requires Node.js 22+ and npm. In this directory:

```sh
npm ci
npm test
npm start -- init
npm start -- status
npm start -- airdrop 1
npm start -- create 0.05
npm start -- fund 0.01
npm start -- send 0.005
npm start -- status
```

In this working directory, `init` has already been run and throwaway keys are present in `./keys`: skip that step when continuing the demo. The public RPC faucet returned 429 during verification, so the remaining live steps require permitted devnet-only funding of the generated payer. Do not use existing keys, mainnet SOL, or the official web faucet as an AI agent (its site explicitly asks agents to use programmatic alternatives).

`send` accepts an optional devnet recipient address after the SOL amount; by default it sends to a newly generated throwaway recipient. `create` deposits SOL into the Quip wallet at creation, while `fund` makes a plain fee-payer-to-Quip-PDA deposit; **only `send` uses Quip's WOTS+ PQ authorization** (in addition to the ordinary Solana fee-payer signature). Funding and airdrops need faucet availability. Commands use only `https://api.devnet.solana.com` and verify the devnet genesis hash before any network operation. Addresses and transaction signatures are printed but secrets are not.

All test keys and vault data are freshly generated by `init` inside `./keys` (mode 0700 with 0600 files); `init` refuses to replace an existing `keys` directory. Do not commit/ship/repurpose them. No existing machine wallet or Solana CLI configuration is read. The project ignores `keys/`. The CLI records each attempted WOTS public seed in `keys/wots-attempts.json` *before signing*; a failed chunked transfer cannot be retried with the same one-time key. A `keys/send.lock` file prevents simultaneous send processes; if one crashes, inspect the on-chain state and journal before removing the lock yourself. Review on-chain state manually if a transfer fails. A successful transfer rotates the on-chain WOTS key and permits the next `send` with the new key. The SDK's chunked transaction helper sends several devnet transactions; the CLI reports the final transfer signature and verifies it on-chain.

The published SDK uses extensionless ESM imports which native Node cannot resolve. `npm start` and `npm test` first locally bundle the installed vendor SDK to `dist/quip-sdk.cjs` via esbuild (`--packages=external`), without modifying the vendor package. No server, Docker, browser, or mainnet account is needed. Vendor SDK is AGPL-3.0-or-later; review license obligations for redistribution.
