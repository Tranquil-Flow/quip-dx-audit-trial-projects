# Quip Network Developer Experience Audit: trial projects

Source code that AI coding agents built while testing how easy it is to build on Quip Network from the public docs alone. These are the working artefacts behind the *Developer Experience Audit (August-October 2026)*; trial IDs here (`t01-a`, `m3-b`, ...) match the report and its trial cards.

**How to browse:** each trial lives on its own branch, `trial/<id>`. Pick a row below, open the branch, and start with `TRIAL.md` (what it built, which Quip products it touched, the evidence, what got in the way). `RESULT.md` and `DEVLOG.md` are the builder's own write-ups; `EXCLUDED.md` lists what was left out.

89 of 97 trials have source on a branch. The rest are listed with their report card but no code (see below).

## Running a project

- [`docs/RUNNING.md`](docs/RUNNING.md): how to get a project running with your own test accounts, common pitfalls, and a table of every project's stack. Each `trial/<id>` branch also has its own `RUNNING.md`.
- [`docs/AGENT_PROMPT.md`](docs/AGENT_PROMPT.md): a prompt you can hand to an AI agent to repair a project with your own throwaway accounts.
- [`docs/REDACTIONS.md`](docs/REDACTIONS.md): exactly what was removed or replaced before publishing, and why the test-account values in logs and fixtures were left in.

In short: key files, dependencies, clones of Quip's own repositories and large files are not included; only personal details were replaced; the test-account values the agents left in logs and fixtures were kept after checking that none holds mainnet value. Projects were not edited to make them run.

## Rounds 3-5: recovered projects

The rounds 3-5 agents (trial ids starting `g`, `v`, `p`, `s` and `x`) worked in temporary folders that were deleted after the audit. 42 of their 50 projects are on branches; the other 8 have their card only.

**Where the files came from.** Three trials, `x1-a`, `x1-b` and `x2-a`, ran on a separate Linux server where their folders were kept. The `x1` branches are copies of those folders; `x2-a` was recovered as described below and then matched its original folder file for file. For the rest, the agent runner used for most of these trials keeps a snapshot of the working folder before each file the agent writes (only the latest snapshot per folder survives). Each branch starts from the last snapshot of either the trial's own folder or the copy that an independent rebuild made of the finished project. The session log of each run records every file the agent wrote or patched, with the content or the exact patch.

**How each branch was made to match the trial's own result.**
- Files the agent wrote or patched after the last snapshot were rebuilt from the log (its last full write plus every later patch). They are listed in the branch's `RESTORED.md`.
- Where a rebuild run had changed one of the trial's files, the trial's own version was put back (also in `RESTORED.md`). Files a rebuild added, such as its own check scripts, were removed and are listed in `EXCLUDED.md`.
- Files the agent deleted itself before finishing were removed.

**What you can rely on.**
- **Checked against the log (32 branches, including `x2-a`):** every file the agent wrote or patched is present in its final version, except the ones it deleted.
- **Not checkable file by file (8 branches: `g1-a`, `g4-a`, `g6-a`, `p1-a`, `p3-a`, `v1-a`, `v3-a`, `v7-a`):** these ran in Claude Code, which keeps no snapshots, so they come from a rebuild's copy of the finished project. The agents mostly wrote files through shell commands, so the log cannot confirm each file. Files the rebuild added were removed.
- **`x2-a`:** recovered from a rebuild's copy like the others, then compared with the agent's original folder on the server: it matches file for file.
- **Possible gaps everywhere:** a file that a program wrote after the last snapshot and that the agent never wrote or patched itself, for example a result file produced by the final run, may be missing or an earlier version.
- **Evidence is on the old chain:** Aglais was relaunched from a new genesis in October 2026, so the Aglais transactions and addresses in these notes are on the earlier chain and no longer resolve. Base Sepolia evidence still resolves.
- **Removed on purpose:** keys, dependencies, caches, clones of Quip's repositories and files over 1 MB (see each `EXCLUDED.md` and [docs/REDACTIONS.md](docs/REDACTIONS.md)). Three earlier runs that the report does not count are not published.

## What you are looking at

- **Each project is kept as the agent left it.** Nothing was fixed or polished. Many are partly working or blocked on purpose; the point is where a developer gets stuck.
- **Neutral IDs.** The letter after the dash only separates builders on the same brief. The model that did each build is named in the table.
- **Rounds.** Round 1: single-product builds (`t*`). Round 2: simulated developers and multi-product builds (`h*`, `m*`). Later rounds (`g*`, `v*`, `p*`, `s*`, `x*`) were run in temporary directories that were later deleted. Most of those projects were recovered from the agent runner's file snapshots and session logs (see [REDACTIONS.md](docs/REDACTIONS.md), section 5); the rest are listed with their card only.
- **Builders worked only from public docs and the public internet, on testnets, with throwaway keys.**
