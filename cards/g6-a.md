## Trial card

- **Model:** Claude Sonnet 5.5.
- **What it does:** A Node signer makes a throwaway SHRINCS (256s-keccak) key with `hashsigs-wasm` and signs a 32-byte hash. The builder deployed Quip's SHRINCS256sKeccak ERC-7913 verifier on Aglais, plus a small `PQGate` contract that pins a key commitment and accepts each hash once only if the verifier returns the success selector.
- **Quip products and integration:** `@quip.network/hashsigs-wasm` signing — NATIVE; the verifier contract (from the `shrincs-main` branch) and the gate — SELF_DEPLOYED on Aglais, since Quip publishes no canonical verifier there; Aglais EVM — CHAIN_ONLY.
- **Evidence:** Verifier deploy [0x045c9214a949860bd7e3a89349fe653d778c0615f4c35680816ce021c4132efd](https://explorer.aglais.quip.network/tx/0x045c9214a949860bd7e3a89349fe653d778c0615f4c35680816ce021c4132efd) creating [0x145968ae1D26B342D699F3b147BB25308C2CF05c](https://explorer.aglais.quip.network/address/0x145968ae1D26B342D699F3b147BB25308C2CF05c); gate deploy [0xc1759223b1bc028ef9c0efa088d69db4185171bf919e9a10056b6c4640522f32](https://explorer.aglais.quip.network/tx/0xc1759223b1bc028ef9c0efa088d69db4185171bf919e9a10056b6c4640522f32) creating [0xE537c8fb865CE53b29172aec1AdbAC5b6D59416f](https://explorer.aglais.quip.network/address/0xE537c8fb865CE53b29172aec1AdbAC5b6D59416f); in-contract verification [0x344b7d2ee5fe582586079fb598b782930c78ed73170d69919c05fd719fc4c0e9](https://explorer.aglais.quip.network/tx/0x344b7d2ee5fe582586079fb598b782930c78ed73170d69919c05fd719fc4c0e9) (status 1, about 12.1M gas, `accepted` true); an earlier attempt [0x74cd6122d652e47d38ebd878769e57187e5910db9bb8c29bd05f5e60652fb8d8](https://explorer.aglais.quip.network/tx/0x74cd6122d652e47d38ebd878769e57187e5910db9bb8c29bd05f5e60652fb8d8) failed (status 0) at an 8M gas limit. The same signature is rejected by Quip's live V4 verifier, because the `shrincs-main` verifier is the older v1 format; the builder's note calling it the current V4 verifier was wrong. First rebuild: works, with its own verification [0x7750f6b9703b3b390c56bdb0716e02a3df0e1a9e5493478248372a113598a5a7](https://explorer.aglais.quip.network/tx/0x7750f6b9703b3b390c56bdb0716e02a3df0e1a9e5493478248372a113598a5a7). Second rebuild: works; it also hit a `forge create` that printed "Deployed to" for a failed transaction and had to redeploy with RPC-estimated gas.
- **Time:** 7 min.
- **What got in the way:** Aglais EVM coordinates are not in the developer docs [[C-AGT-05](https://developers.quip.network/docs/llms-full.txt)]. The docs still call WOTS+ "preferred" [[C-ACC-15](https://developers.quip.network/docs/getting-started/quickstart#:~:text=especially%20the%20preferred%20Winternitz%20One-Time%20Signature%20%28WOTS%2B%29)]. The SHRINCS Solidity verifier is not on the `main` branch or npm [[C-SDK-13](https://gitlab.com/quip.network/hashsigs-solidity/-/tree/e92d0b954b47f6c881bcf6736ee2bff64f84e77b/contracts)], several branches use incompatible signature formats and nothing maps them to library versions [[C-R5-15](https://gitlab.com/quip.network/hashsigs-solidity/-/blob/oak-03-and-06/contracts/SHRINCSVerifier.sol)], and Quip's deploy scripts cannot run on Aglais because CreateX is not deployed there [[C-R5-16](https://gitlab.com/quip.network/hashsigs-solidity/-/blob/oak-03-and-06/contracts/SHRINCS256sKeccak.sol)]. The `foundry.toml` fails on forge 1.5.1 [[C-SDK-24](https://gitlab.com/quip.network/hashsigs-solidity/-/blob/0e89278f573a29f8341e1f5697ea73e0f8988d51/foundry.toml#L32-L40)]. The `hashsigs-wasm` README does not show how to feed a signature to the verifier [[C-TRL-05](https://data.jsdelivr.com/v1/packages/npm/@quip.network/hashsigs-wasm@0.2.1-rc9)]. Verification costs about 12.1M gas and an 8M limit fails with no reason [[C-TRL-30](https://explorer.aglais.quip.network/tx/0x9347459212a9432002a11ea44bd7561ba156a51e7512f82b1304f8d6465464f4)]. The documented `cast codehash` check does not work on the Aglais RPC [[C-R5-17](https://gitlab.com/quip.network/hashsigs-solidity/-/blob/oak-03-and-06/DEPLOYMENTS.md)].
