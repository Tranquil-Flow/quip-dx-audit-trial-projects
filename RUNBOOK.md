# Devnodeb Aglais testnet ops runbook

Working directory: `/home/dev2/projects/proj-7db143`. ONLY operate `devnodeb-quip` compose project (`compose.yaml`) and `devnodeb-node` / `devnodeb-miner`. Do not use vendor-nodes' compose, Makefile, cron, `--remove-orphans`, or global container names. Chain and secrets persist in `./data/chain` and `./keys` respectively; do not print or copy private key contents. Both images run as uid 1000 to read the shared node key: the miner always chowns `./keys` to uid 1000 and enforces 0600 on the signer. Host uid 1003 cannot directly enter it. This is expected. For a config edit after stopping both containers, temporarily change ownership of ONLY the project `./keys` directory using a disposable `devnodeb-` prefixed root Docker container, edit `keys/config.toml`, then return ownership to 1000:1000 BEFORE starting either service. Never relax private-key permissions. Do not enable `--sync=warp`: this validator image panicked in tests on both fresh and partly synced databases.

Start / restart: `docker compose -f compose.yaml up -d node`, wait until `python3 verify.py` prints `NETWORK_SYNCED: True` (it may report miner telemetry unavailable until the next step), then `docker compose -f compose.yaml up -d miner`. Do NOT bring up both simultaneously against a node that is still catching up: a momentary 0-peer startup state on a partly synced DB fooled this coordinator into attempting faucet funding against stale local state. First sync may take tens of minutes or longer. Both containers have `restart: 'no'` so an explicit start is needed after reboot. Never start against another chain spec, especially mainnet. Do not run the image's default chain preset; the mounted Aglais spec has canonical genesis `0x59e064bddd49a920d1392693c728c3bf9867f2cf3e0f8fea8c2498b389b0c286`.

Stop: `docker compose -f compose.yaml stop` (does not wipe chain or keys; only project containers). `docker compose -f compose.yaml ps -a` confirms their state. Avoid `down -v`.

Logs: `docker compose -f compose.yaml logs -f --tail=100 node miner` (Ctrl-C ends only the log follower). For status, `python3 verify.py` compares local/public genesis, runtime, best heights, finalized block hashes/heights and peer/sync state; `NETWORK_SYNCED: True` requires best and finalized heights within 16 blocks, matching hash at a common finalized height, matching runtime/genesis, non-syncing state and peers. Local read-only JSON-RPC: `http://127.0.0.1:31200`; miner API once running: `http://127.0.0.1:31202/api/v1/status`, work attempts via `http://127.0.0.1:31202/<qblock_id>/attempts.jsonl`. P2P is on loopback only `31201/tcp+udp` mapped to container 30333. This is outbound-only participation: no inbound connections from internet, by request; do not change firewall/binding without explicit approval. Vendor recommends publicly reachable `30333/tcp+udp` for useful inbound peering, and `20049/tcp` for dashboard/RPC if enabling their public UI; neither is exposed here. Miner descriptor advertises loopback-only placeholder `127.0.0.1:31200`, NOT a public URL.

Upgrade: read upstream `nodes.quip.network` release notes and the `quip-validator`/`quip-miner` release notes, check new version still supports Aglais and matching spec. `docker pull registry.gitlab.com/quip.network/quip-validator/quip-network-node:beta` and `docker pull registry.gitlab.com/quip.network/quip-miner/v0.3/quip-miner:beta`; review `docker image inspect` / pull digests, edit only the two pinned `image: ...@sha256:` values in our `compose.yaml`, and verify `docker compose -f compose.yaml config`. Stop OUR miner (`docker compose -f compose.yaml stop miner`), `docker compose -f compose.yaml up -d node`, wait for `python3 verify.py` to return `NETWORK_SYNCED: True`, then `docker compose -f compose.yaml up -d miner`. Watch logs and verify it resumes work. Keep old image digests and chain state for rollback, but a chain reset/genesis change requires an entirely new project-local chain directory (never reuse an incompatible database). Never run vendor auto-upgrade scripts on this shared server.

Security: Loopback-only host publishes, no firewall changes. `--rpc-methods=safe`; the RPC listens within the private compose network so the miner can connect. Docker access is root-equivalent; keep Docker membership and `./keys` restricted. No real-money transactions, no mainnet, only brand-new auto-generated testnet signer and libp2p keys.
